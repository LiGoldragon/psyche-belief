Where two concerns are tied into one knot, the abstraction under the knot is redone. The knots:

- a branch that exists for one caller, one host, one file or one moment;
- the same effect sought by a second design when the first fails;
- a boolean parameter that makes one function behave as two;
- an integer or a string whose meaning is only in its name: the meaning is a type;
- a name, a path, a command or a message written as a literal in code: it is data, held in a datom field;
- a fact held in two places that must agree.

A design names the event each action answers, and the system is quiet when nothing has happened.

A name spells out what the thing is, whole: FrontMatter, ProgrammingLanguage. A type is named for what it holds: SessionId holds a session's id, and Session is the session.
