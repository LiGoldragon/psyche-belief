A launch can be rehearsed: the same input, asked as a dry run, answers with the whole command the Flow Nexus would run and runs nothing. From that command an agent starts the flow by hand, changed however the Flow Nexus does not yet support. The answer is one string, the command line as the shell is to receive it, quoted for the shell inside.

One call sends several requests to one receiver, and they reach it together, in one prompt, in the order written: his words and the order about them arrive as one thing, and the sender pays for one call.

## The Flow Nexus sends no notification unasked; a flow asks what it needs to know

```mermaid
flowchart TB
    d["something was done: work cancelled, closed, delivered, finished"] -- "the Flow Nexus, unasked, notifies" --> z["no flow"]
    f["a flow that needs to know where a thing stands"] -- "asks, when it needs it" --> n["the Flow Nexus"]
    n -- "answers, once" --> f
    m["an automated message"] -- "wakes a flow gone cold, which reads its whole context again" --> x["dear"]
    m -- "stays in the context of every flow it reaches" --> x
```

The Flow Nexus sends no notification that was not asked for. The answer to a call is the whole of what its caller is told, and no message follows it. A flow that needs to know where a thing stands asks, when it needs to know; the Designer above all is sent no notification of what got done.

An automated message is dear: it can wake a flow gone cold, which then reads its whole context again, and it stays in the context of every flow it reaches. So every notification the Flow Nexus can send is configuration, and its quiet setting is the default.

## The simple request sends no notification

```mermaid
flowchart TB
    s["a flow sends work, the simple form"] -- "is delivered; done or cancelled, its sender is sent" --> q["no notification"]
    v["a flow sends work, the verbose form, naming the outcomes it wants to be notified of"] -- "is delivered with an id" --> r["the receiver"]
    r -- "says it is done" --> n["the Flow Nexus"]
    c["another cancels it"] -- "Cancel" --> n
    n -- "the outcome is among those the sender named" --> t["the sender is notified, once"]
    n -- "the outcome is not among them" --> q
```

Every request has a simple form and may have a verbose one. The simple form is free of noise: its sender is sent no notification. Whatever adds noise is asked for, in the verbose form, which sets out as configuration each notification its sender receives.

```mermaid
flowchart TB
    w["Work: the quiet request"] -- "done or cancelled" --> q["no notification"]
    n["NotifiedWork: the simple notified request"] -- "done or cancelled" --> d["one notification, to the Nexus's default notification destination for that type"]
    v["NotifiedWorkWithDestinations: the verbose request"] -- "names each type it wants notified, and for each" --> c["one destination or several"]
    c -- "the work has an outcome of a named type" --> t["one notification to each destination named for it"]
    c -- "the outcome's type was not named" --> q
```

```ethos sketch
Types
[ Work.String
  NotifiedWork.String
  Notified.{ NotificationType Vector<Address> }
  NotifiedWorkWithDestinations.{ String Vector<Notified> }
  WorkNotification.{ RequestId NotificationType For.Address } ]
```

Work is quiet. NotifiedWork is as simple, the work alone: every type of notification goes to the Nexus's default notification destination for it. NotifiedWorkWithDestinations is the verbose one: the work, then each type of notification it asks for, with the destinations it goes to. A WorkNotification names the work by its id, its type, and the flow whose work it was. A flow is never notified of what it did itself: a sender that cancels its own work has the answer to its call.

Work sent quietly; work notified to the default notification destinations; work whose finishing is notified to two flows the request names; and a notification, as it reaches a destination. The texts, the addresses and the id are examples.

```datom
Send.{ { Mind core Sol } Soft.Work.«Review the drain fix.» }
Send.{ { Mind core Sol } Soft.NotifiedWork.«Review the drain fix.» }
Send.{ { Mind core Sol } Soft.NotifiedWorkWithDestinations.{ «Review the drain fix.» [ { WorkDone [ { Psyche heartbeat Luna } { Psyche core Astra } ] } ] } }
[ { Notification Soft.WorkNotification.{ k7ph WorkDone { Psyche core Fable } } } ]
```

## A notification goes to a destination

```mermaid
flowchart TB
    n["a notification of one type"] -- "the request named destinations for that type" --> a["each of those destinations"]
    n -- "the request named none" --> d["the Nexus's default notification destination for that type"]
    d -- "may be" --> h["the heartbeat, a cheap flow"]
```

A notification goes to a destination, which is a flow. The Flow Nexus holds one default notification destination for each type of notification, for all its flows, set as configuration and changed there while the Nexus runs.

```ethos sketch
Types
[ NotificationType.[ WorkDone WorkCancelled ]
  DefaultNotificationDestination.{ NotificationType Address } ]
```

Notifications of finished work sent to the heartbeat. The address is an example.

```datom
Configure.DefaultNotificationDestination.{ WorkDone { Psyche heartbeat Luna } }
```

## A flow is a thought flow

A flow is a thought flow of a thinking machine, run in one session of a harness. A permaflow is the series of flows under one address, and the thought continues through the series: each flow ends in a crystallization and the next starts from it. A flow with a goal unachieved is acting; a flow with none is resting.

A session is what a harness sets up to run a flow: dry until its first prompt is submitted, and flowing from then.

```mermaid
flowchart TB
    p["a permaflow: one address"] -- "is a series of" --> f["flows: each one session"]
    f -- "ends in" --> c["a crystallization"]
    c -- "starts the next" --> f
```

## The efficient window

Each model has an efficient window: the size of context within which a flow is worth continuing. Its upper end is set below the size at which the harness compacts on its own. A flow goes cold when its cache life has passed since its last turn. The window, the cache life and the margin are configuration, one record per model; the investigator is the address told of what went wrong.

```ethos
Library
[ flow:[ Model Address ModuleName ] ]
[ Tokens.Integer
  Minutes.Integer
  EfficientWindow.{ Model
                    UpperEnd.Tokens
                    CacheLife.Minutes
                    CoolingMargin.Minutes }
  CrystallizationGuide.{ Address ModuleName }
  Investigator.Address ]
[]
[]
```

A CrystallizationGuide names, for one permaflow, the module that says how its kind of flow crystallizes. The figures and the module name below are examples.

```datom
EfficientWindow.{ Sol 150000 30 5 }
CrystallizationGuide.{ { Mind flowNexus Sol } knowledge:crystallization-implementer:0 }
Investigator.{ Psyche core Opus }
```

## A flow's state is a record of events

The Flow Nexus holds a flow's state as the last of its transitions, each recorded with the event that caused it, for every harness alike. The harness's Nexus tells it, by subscription, each event of a session and the state it leaves; the Flow Nexus's own clock and the requests it delivers are causes as well.

```mermaid
flowchart TB
    h["Harness Nexus: Changed, a session, its event, its state"] -- "state Flowing.Working, or Flowing.Waiting on work in flight" --> w["Reported.Working, with the context's size"]
    h -- "state Flowing.Rested" --> i["Reported.Idle, with the context's size"]
    h -- "event Compacted" --> c["Reported.Compacting"]
    h -- "state Ended" --> e["Reported.Ended"]
    h -- "state Dry" --> s["Reported.Started"]
    i -- "inside the window" --> k["the cooling clock is set"]
```

## A resting flow crystallizes before it goes cold, and sleeps

When a flow comes to rest inside its window, the Flow Nexus sets one clock, the cooling margin short of the cache life, and sends the flow nothing. A request that arrives is delivered and cancels the clock. When the clock fires, or at once when the flow rests past the upper end, the Flow Nexus asks the flow to crystallize, once, with its guide's text in the same prompt. The flow answers that it rests, and the permaflow is asleep: its crystallization is kept for its next flow. An OnDemand permaflow's harness is closed; a Maintained one's pane stays on screen for the living to read.

```mermaid
flowchart TB
    a["Acting"] -- "the harness reports Idle, with the context's size" --> r["Resting"]
    r -- "inside the window: the Nexus sets the cooling clock" --> k["Resting, clock running"]
    k -- "a request arrives: clock cancelled, delivered" --> a
    k -- "the clock fires, before the cache lapses" --> c["Crystallizing"]
    r -- "past the upper end: at once" --> c
    c -- "the flow answers Resting" --> s["Asleep: crystallization kept"]
```

The Flow Nexus asks, and the flow answers; the request names the guide and the file to write.

```ethos
Signal
[ flow:[ RequestId ModuleName Onward ] ]
[ Crystallized.{ RequestId Onward } ]
[ Slept
  Continued ]
[ FilePath.String
  Crystallize.{ RequestId ModuleName FilePath } ]
```

```datom
[ { Notification MiddleAbrupt.Crystallize.{ c4d1 knowledge:crystallization-implementer:0 «flows/5441e0/crystallization.md» } } ]
Crystallized.{ c4d1 Resting }
Slept
```

## An acting flow continues in a fresh flow

When an acting flow's context reaches the upper end of its window, the Flow Nexus asks it to crystallize, once, at its next tool boundary. The flow finishes what it has in hand, crystallizes with its goal and its next act, and answers that it continues; the Flow Nexus starts a fresh flow of the same permaflow from that crystallization and the open requests, and closes the old flow when the new one reports Started. No flow is ended for its size alone.

When the harness announces a compaction, the Flow Nexus asks for the crystallization then, pressing, and tells the investigator; crystallization is the flow's own compaction, made by its kind's guide.

```mermaid
flowchart TB
    w["the harness reports Working, the context's size at the upper end"] -- "Nexus sends Crystallize, once, MiddleAbrupt" --> c["Crystallizing"]
    h["the harness reports Compacting"] -- "Nexus sends Crystallize, HardAbrupt, and tells the investigator" --> c
    c -- "the flow answers Continuing, its next act named" --> n["a fresh flow: crystallization, then the open requests"]
    n -- "reports Started" --> x["the old flow is closed"]
    n -- "acts in its first turn" --> a["Acting"]
```

```datom
Crystallized.{ c4d1 Continuing.«Run the codec tests, then mend the two that fail.» }
Continued
```

A flow started to continue acts in its first turn. One that reports Idle after Started with no Working between them is a useless refresh, and the investigator is told.

## What wakes a sleeping permaflow

A request for a sleeping permaflow starts a fresh flow from its crystallization, with its queue, oldest first; a notice alone waits for the next waking. A resting flow whose clock still runs is hot and inside its window, and receives the request itself. A cold flow is never woken.

```mermaid
flowchart TB
    m["a request for a permaflow"] -- "Asleep; an order, question, task, his words, a result or a done" --> f["a fresh flow: crystallization, then the queue"]
    m -- "Asleep; a notice" --> q["queued for the next waking"]
    m -- "Resting, clock running" --> d["delivered to the same flow"]
    m -- "Acting" --> d
    m -- "Crystallizing" --> q2["queued for the flow that follows"]
```

## The override panel

Whatever the Flow Nexus holds or does on its own can be set or done by hand on the meta socket, so that a fault is worked through the Nexus and never around it. Each override is recorded as a transition with its cause, Overridden. Hold is the shutdown switch: the Flow Nexus stops acting on its own, its clocks, its deliveries and its launches, and still answers; Resume lets it act again.

```ethos
Signal
[ flow:[ FlowId Address State ] ]
[ SetState.{ FlowId State }
  CrystallizeNow.FlowId
  Renew.Address
  Close.FlowId
  Deliver.Address
  Unlock.Address
  Forget.FlowId
  Hold
  Resume ]
[ StateSet.{ FlowId State }
  Asked.FlowId
  Renewed.FlowId
  Closed.FlowId
  Delivered.Address
  Unlocked.Address
  Forgotten.FlowId
  Held
  Resumed
  Refused.[ UnknownFlow.FlowId
            UnknownAddress.Address ] ]
[]
```

SetState corrects the state the Nexus holds for a flow; CrystallizeNow asks a flow for its crystallization whatever its state; Renew starts a fresh flow of a permaflow from its crystallization and closes the old one; Close closes a flow's harness; Deliver hands a permaflow its queue now; Unlock releases a permaflow's lock; Forget removes the record of a flow that has no harness.

```mermaid
flowchart TB
    o["the owner, at the meta client"] -- "SetState, CrystallizeNow, Renew, Close, Deliver, Unlock, Forget" --> n["the Flow Nexus"]
    n -- "records the transition, cause Overridden" --> m["Memory"]
    o -- "Hold" --> h["the Nexus stops acting on its own, and still answers"]
    h -- "Resume" --> n
```

The flow that was held as working, corrected and renewed through the Nexus:

```datom
SetState.{ 5441e0 Resting }
StateSet.{ 5441e0 Resting }
Renew.{ Mind flowNexus Sol }
Renewed.918fa4
```
