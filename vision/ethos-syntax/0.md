How an Ethos file is written. Position carries the meaning: no field names, no keywords, nothing written twice.

## A Library

```ethos
Library
[ :protos:Textualizable ]
[ Name.String
  Word.String
  Import.{ Namespace.⟦Word⟧
           ⟦Name⟧ }
  Declaration.{ Name Type }
  Variant.{ Name Option<Type> }
  Type.[ Name
         Import
         Declaration
         Struct.⟦Type⟧
         Enum.⟦Variant⟧
         Vector.Type
         Applied.{ Name ⟦Type⟧ } ]
  Bound.⟦Name⟧
  Receiver.[ Shared Mutable Absent ]
  Capability.{ Word Receiver ⟦Type⟧ Type }
  AssociatedType.{ Name Bound }
  Constant.{ Name Type }
  Trait.{ Name ⟦Bound⟧ Bound ⟦AssociatedType⟧ ⟦Constant⟧ ⟦Capability⟧ }
  Association.{ Name Bound }
  Library.{ ⟦Import⟧ ⟦Declaration⟧ ⟦Trait⟧ ⟦Association⟧ }
  Signal.{ ⟦Import⟧
           Inputs.⟦Variant⟧
           Outputs.⟦Variant⟧
           ⟦Declaration⟧ }
  Ethos.[ Library Signal ]
  Refusal.[ Import
            Collision.Name
            LoneVariant.Declaration
            Wrapper.Declaration
            Unreadable ] ]
[ Checkable.[ check.[ ⟦Refusal⟧ ] ]
  Readable.[ read:{ [ Textualizable ] [ Result<Self Refusal> ] } ]
  Expandable.[ expand![ ⟦Refusal⟧ ] ]
  Rooted.{ [ Checkable Readable ]
           [ Generated<Textualizable> ]
           [ SECTIONS.Integer ]
           [ generate.[ Result<Generated Refusal> ] ] } ]
[ Library.[ Rooted Expandable ]
  Signal.[ Rooted Expandable ]
  Ethos.[ Checkable Readable Textualizable ] ]
```

This file is Ethos, described in Ethos; ethos-zero checks it. The sections, by position: imports, types, traits, associations. An empty section is `[]`.

| in the file | is |
|---|---|
| `Name` | a newtype: a head over a scalar |
| `Declaration` | a struct: all of these, by position |
| `Receiver` | an enum: one of these, two at least; each variant carries nothing |
| `Bound` | a vector, written tight |
| `Type` | an enum; its variant `Name` is a defined type and carries it, `Struct` carries a vector, `Applied` declares its payload inline |
| `Namespace`, in `Import` | a type declared where it is used |
| `Signal` | two positions of one type, so each takes a name |
| `Library` | its four positions are the four sections of this file |
| `check` | `.` takes self; the bracket is the yield, one type |
| `expand` | `!` takes mutable self |
| `read` | `:` takes no self; the inputs, then the yield; an input is a trait |
| `Rooted` | a complex trait: supertraits, associated types, constants, capabilities |
| the last section | each type bears its traits; each capability's body is hand-written Rust |

Known without import: String, Integer, Decimal, Boolean, Meaning, Option, Result, Self, Sized.

## Imports written inline

```ethos
Library
[]
[ Topic:custom:Name
  Failure.{ :protos:Error String } ]
[]
[]
```

`Topic` is declared over `Name` of the namespace `custom`; the first position of `Failure` is imported where it is used.

## A Signal

```ethos
Signal
[]
[ Lock.LockRequest
  Release.LockId ]
[ Locked.Lock
  Released.Lock ]
[ LockId.Integer
  LockName.String
  FlowId.String
  LockRequest.{ LockName FlowId }
  Lock.{ LockId LockName } ]
```

The sections, by position: imports, inputs, outputs, types. Another file imports what it generates as `:signal_flow:signal:[ Input Output ]`, the namespace named for the root.

## An Emission

```ethos
Signal
[]
[ Command.{ Verb ⟦Argument⟧ } ]
[ Outcome.[ Done Refused.Integer ] ]
[ Verb.[ List Show ]
  Argument.[ Name.String Quiet ] ]
```

Today an Emission is written as a Signal in a file named `emission.ethos`: its inputs are the emissions, its outputs the outcomes.

## Refused

| refused | why |
|---|---|
| an enum of one variant | an enum is a choice |
| a head that only wraps another named type | a type that has a name is used by its name |
| an import that does not resolve, a name declared twice | refused while the file is read, before any Rust exists |
