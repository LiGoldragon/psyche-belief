## The CLI

The `flow` on PATH is the Flow Nexus's ordinary client and `flow-meta` its meta client. Each takes one datom argument and nothing else. A configuration that is missing, unreadable or invalid is refused naming the file (exit 2), and nothing is sent.

```sh
flow 'Send.{ { Psyche core Fable } Soft.Notice.«The build is green.» }'
```

A flow sends to an address it already knows. To learn which permaflows exist or what they do, it asks the cheap core flow of its own aspect, { Psyche core Sonnet }, { Mind core Sol } or { Field core Sol }, which answers with the few addresses that bear on the question.

## The Send input

An address names its model: { Psyche core Fable }, { Mind core Astra }. Any model stands in any aspect. The recipient is the address, written bare.

```ethos
Send.SendRequest
SendRequest.{ Address SendableMessage }   ; the recipient, then the message
Address.{ Aspect Topic Model }
Aspect.[ Psyche Mind Field ]
Topic.String                              ; an uncapitalized camelCase identifier
Model.[ Fable Opus Sonnet Haiku Astra Sol Luna Terra ]
Context.String                            ; what the living's words were about
Verbatim.String                           ; his words whole
Minutes.Integer
AnswerableTask.{ Minutes String }
RequestId.String                          ; four characters, 0-9 and a-z
SendableRequest.[ Order.String
                  Question.String
                  Living.{ Context Verbatim }   ; one saying; several are several Sends
                  Result.{ RequestId String }   ; answers the Question it names
                  Notice.String
                  Task.AnswerableTask
                  Done.{ RequestId String } ]   ; closes the Task it names
SendableMessage.[ HardAbrupt.SendableRequest
                  MiddleAbrupt.SendableRequest
                  Soft.SendableRequest ]
```

Only what asks wakes a sleeping permaflow, starting a fresh flow for it: an Order, a Question, a Task, Living, a Result or a Done. A Notice alone waits in the queue for the next waking, whatever its priority. The priority says how a running or resting hot flow is reached: HardAbrupt interrupts it, MiddleAbrupt arrives at the next tool boundary, and an abrupt Notice reaches a resting hot flow at once, where a Soft one queues. A sender that needs a sleeping flow to act sends a Question or an Order.

A Soft request waits in the queue while its recipient works, and is delivered when it rests; a flow can work for hours without resting. A request that must reach a working flow soon is sent MiddleAbrupt.

Text is a String, written in guillemets: «text». A datom holding an apostrophe goes through a shell variable, since the argument is single-quoted. Inside guillemets a double quote is written bare, and only an unbalanced guillemet is escaped; the single-quoted argument passes every character as written, a backslash too.

A message is written as ordinary English sentences, a space between every two words.

Every request reaches its recipient with its RequestId, which Flow draws when it admits the Send.

A Result answers a Question and a Done closes a Task, each naming the request by its RequestId. An Order is closed when it is delivered; a Question stays open until its Result, a Task until its Done. One answer closes a request, and the Flow Nexus routes it to the sender of the request it names.

## Its reply

`Sent.<RequestId>` says the message was placed in the recipient's pane and received. `SendAccepted.{ <RequestId> <cursor> Queued }` says it waits in the recipient's queue; the RequestId is kept and the message is not sent again. `Uncertain` in place of `Queued` says it may have been placed; it is not sent again either. Every other reply, and what to do when Flow cannot deliver, is in knowledge:flow-message-replies:0.

Reminders, cancelling and closing a request, reading the queues and refreshing a held permaflow are in knowledge:flow-control:0.

## Examples

```sh
flow 'Send.{ { Mind core Astra } Soft.Task.{ 30 «Review the fix.» } }'
flow 'Send.{ { Psyche core Fable } Soft.Living.{ «the drain» «Fix it today.» } }'
flow 'Send.{ { Mind core Astra } Soft.Done.{ m2x9 «Reviewed; green.» } }'
```

## A flow's own refresh

`flow 'Refresh.{ <Aspect> <topic> <Model> }'`, naming the flow's own Address, answers `RefreshQueued` while the flow works: the refresh is carried out at its next rest, ending its background work, and until then the flow still receives what is sent to it. A resting flow is refreshed at once, answered `Refreshed`.
