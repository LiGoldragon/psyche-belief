## Reminders

`flow 'Remind.{ <Address> <Minutes> «text» }'` sends that address a MiddleAbrupt Reminder, from whoever asked, after the minutes; `flow 'Cancel.<RequestId>'` ends it before then.

A Task whose minutes pass with no Done reminds its sender once, at Soft; the sender then asks the recipient where the Task stands.

## Answers

A Result or Done is admitted only when its request was delivered and is still open; otherwise it is refused Unresolved. The Flow Nexus routes an answer to the sender of the request it names, whatever address the Send writes. A request whose sender is no address, the living at a shell or Flow itself, keeps its answer, and `flow 'Answer.<RequestId>'` reads it. An Order is carried to no successor; an open Question or Task is carried to the recipient's successor.

## Cancelling and closing

`flow 'Cancel.<RequestId>'` closes any open request, an Order, Question or Task among them: the request is archived, leaves the open set a successor is carried, and its queued work is withdrawn. The caller is told by that answer, `Cancelled.<RequestId>`, alone. The recipient gets a Notice only when the request had reached it or its delivery is uncertain; withdrawn queued work tells no one. When another flow cancels, the sender is told nothing. Any caller may cancel any request; Flow checks no ownership.

A Soft request queued behind a working recipient is moved up by cancelling it and sending it again MiddleAbrupt, the new message naming the RequestId it replaces.

`flow 'CloseRequest.<RequestId>'` closes an open request with no answer and tells no one: it leaves its queue if still queued, is archived, leaves the open set a successor is carried, and its reminder goes with it. The caller is answered `RequestClosed.<RequestId>`; no notice reaches the sender or the recipient. Close a request this way only when its work is finished and nobody needs the answer; a Result or Done naming it afterwards is refused Unresolved. It is refused with `CloseRequestRejected.UnknownRequest`, `NotYet` while a delivery of it is being settled, or `Closed`.

## Inspecting

`flow 'Queues'` reads every queue that holds something, each message with its sender and priority. `flow-meta 'DebugDelivery.<RequestId>'` reads one request's delivery and its receipt.

## Configure

Make each change to a permaflow's configuration live and in its authored record in `goldragon-persona` as one task. Update the record that declares the address, including a standalone record where that is its declared form. Read back the live configuration with `flow-meta 'Configuration'` and the matching authored record from the repository. The task is done when both readbacks agree.

## Refreshing a held permaflow

`RefreshQueued` records the refresh for the flow's next rest. `Refreshed` names the ended predecessor when no successor starts at once. `ReapPending` records a confirmed successor whose predecessor is still to be cleaned up.

The address in these commands is an example. Before holding, `flow 'Current.{ Mind exampleSeat Sol }'` names the flow now at the address. While it is current, that flow saves its handover with `Keep`, sees `Kept`, and checks the section with `Read`; an operator reads the handover without contacting the flow.

```sh
flow 'Keep.{ { Mind exampleSeat Sol } { «Handover» «Work and next action» «The handover body» } }'
flow 'Read.{ Mind exampleSeat Sol }'
```

With the handover present and the refresh authorized, the same address is used throughout, each reply confirmed before the next command:

```sh
flow-meta 'HoldPermaflow.{ Mind exampleSeat Sol }'
flow 'Refresh.{ Mind exampleSeat Sol }'
flow-meta 'Inspect.{ Mind exampleSeat Sol }'
flow-meta 'ReleasePermaflow.{ Mind exampleSeat Sol }'
flow-meta 'Inspect.{ Mind exampleSeat Sol }'
```

The release lets Flow take up the pending refresh at its safe boundary. The last inspection, or `Current`, shows a different FlowId at the same address; an on-demand address may instead be asleep until a waking request. `flow-meta 'ReadEvents.<FlowId>'` reads a successor's recorded events without sending it work. `Keep`, `Read`, `Current`, `Refresh` and the meta commands are requests to the Nexus and prompt no flow.
